## 2. Decision

No currently exposed Replit interface available to this project is certified as an authoritative W09-C2N producer.

The correct current result is **PRODUCER UNAVAILABLE / FAIL CLOSED**.

This is not evidence that the current Production database binding is incorrect. It means the exact deployment-to-database resource association cannot presently be proven through a qualifying secret-suppressing producer.

## 3. Current platform evidence

Current Replit documentation establishes that:
- Production databases are managed separately from development databases.
- Replit Production databases use Neon infrastructure.
- Published applications receive database connection information through generated credentials/environment variables.
- Publishing/production-database management surfaces expose connection details to operators for database access.

Those facts establish platform architecture but do not provide the C2N identity object or an immutable deployment-to-provider-resource association.

The documented DATABASE_URL/Secrets path is explicitly ineligible because W09-C2K forbids retrieving a credential and then deriving/redacting identity from it.

## 4. Available structured connector surfaces

The currently available Replit connector exposes:
- publication status: deployment ID, status, public URL;
- app list/search/resolve: app identity/catalog metadata;
- Agent question: natural-language interpretation;
- publish/update: mutations.

It does not expose a structured database-binding resource object containing provider project, branch, database, timeline, endpoint, or immutable binding revision.

Therefore none of these surfaces can produce a C2N PASS object.

## 5. Minimum producer payload

A qualifying producer must emit exactly the closed C2N payload:
- schemaVersion;
- provenanceKind;
- provenanceAuthority;
- replId;
- deploymentId;
- deploymentStatus;
- publicUrl;
- bindingRevisionId;
- provider;
- providerProjectId;
- branchId;
- databaseName;
- timelineId when directly available;
- endpointId;
- observedAt.

It must omit, not redact, credential material.

## 6. Required trust boundary

The producer must run on the authoritative side of the Replit deployment/binding credential boundary:

```
Replit deployment + production DB binding metadata
          |
          | privileged internal resource association
          | (credential values never exported)
          v
authoritative sanitized producer
          |
          | C2N closed payload
          v
pure W09-C2N verifier
```

The producer may not be implemented as application code that reads the deployed process environment.

## 7. Acceptable producer classes

### A. Native Replit control-plane attestation
Preferred. A structured read-only API returns the deployment's sanitized database resource association.

Required authority: Replit control plane.

### B. Replit-supported trusted broker/integration
Acceptable only if the broker can resolve the deployment binding internally without giving raw credentials to project code, the operator, or the assistant, and can attest its Replit authority and exact deployment association.

### C. Independently signed deployment manifest generated by Replit
Potentially acceptable if Replit itself creates/signs the manifest from authoritative binding metadata at deployment time and the manifest is immutable/deployment-bound.

## 8. Rejected producer classes

Not eligible:
- application endpoint reading DATABASE_URL;
- startup code reading DATABASE_URL;
- shell/process environment inspection;
- deployment logs containing connection details;
- operator copying resource IDs into environment variables;
- repository constants/configuration;
- GitHub Actions asserting intended resource IDs;
- Replit Agent prose;
- parsing/redacting a connection string;
- hashing or fingerprinting a connection string;
- DNS inference from credential-bearing host data;
- Neon resource existence without a Replit-side deployment association.

These mechanisms are either secret-observing, self-asserted, or fail independent deployment-binding provenance.

## 9. Why non-secret duplicated metadata is insufficient by itself

Adding `PRODUCTION_DB_PROJECT_ID`, `BRANCH_ID`, or similar non-secret environment variables would make identity visible without exposing credentials, but it would still be operator/application asserted.

Unless Replit's control plane independently binds those fields to the same database resource used by the deployment, they prove only intended configuration, not actual binding.

Therefore a deployment with both DATABASE_URL and manually supplied identity metadata remains UNPROVED under C2I.

## 10. Producer certification requirements

Before a producer may be approved for live use, an offline certification must establish:

1. authoritative Replit/platform provenance;
2. exact repl and deployment input;
3. exact database-binding association;
4. no credential return path;
5. closed output schema compatible with C2N;
6. immutable or freshness-bounded binding revision;
7. missing/ambiguous identity fails closed;
8. deployment change invalidates the receipt;
9. no database session/SQL is required;
10. no provider/public-site mutation is possible;
11. producer cannot substitute operator-supplied resource identity for platform-resolved identity;
12. audit evidence can prove which producer version/mechanism generated the receipt.

## 11. Minimum future platform request

If Replit support/platform engineering must supply a capability, request a read-only operation conceptually equivalent to:

`GetDeploymentDatabaseBinding(replId, deploymentId)`

returning only the C2N sanitized fields and never connection credentials.

The operation should return UNAVAILABLE/NOT_BOUND/AMBIGUOUS rather than falling back to a secret.
